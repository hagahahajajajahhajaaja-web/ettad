# البنية التقنية

## المكدس

- **Next.js 16 (App Router) + React 19 + TypeScript (strict)** بتصدير ثابت `output: 'export'`.
- **Tailwind CSS 4** — نظام الألوان والأدوات المخصصة (زوايا مشطوفة، شريط تحذير، مسطرة قياس) في `src/app/globals.css`.
- **zod** للتحقق من بيانات الكتالوج ومن نموذج الطلب.
- خط **Cairo** مستضاف محليًا (`src/fonts/`، رخصة OFL) — لا طلبات لخوادم خارجية.
- **Vitest** لاختبارات الوحدات و **Playwright + axe-core** لاختبارات المتصفح والوصول.

## الخادم وقاعدة البيانات

`worker/` يُبنى إلى `out/_worker.js` (Cloudflare Pages Advanced mode). `public/_routes.json` يوجّه `/api/*` فقط إلى الخادم، وباقي الملفات تُخدم مباشرة.

| المسار | الوصف | الحماية |
| --- | --- | --- |
| `GET /api/catalog` | الأسعار والتوفر الحالية | عام |
| `POST /api/orders` | إنشاء طلب | نفس المصدر (Origin)، JSON فقط، حد 6 طلبات/10 دقائق لكل IP، تحقق كامل من البيانات، الأسعار تُحسب على الخادم، مفتاح منع التكرار |
| `GET/POST/DELETE /api/admin/session` | حالة/دخول/خروج | مقارنة ثابتة الزمن مع `ADMIN_KEY`، حد 5 محاولات/15 دقيقة، كوكي `HttpOnly; Secure; SameSite=Strict` |
| `GET /api/admin/orders` / `POST /api/admin/orders/:id` | الطلبات وتحديث الحالة والملاحظة | جلسة + نفس المصدر |
| `GET /api/admin/products` / `POST /api/admin/products/:id` | الأسعار والتوفر | جلسة + نفس المصدر |

جداول D1 (تُنشأ تلقائيًا): `product_overrides`، `orders`، `admin_sessions` (تُحفظ بصمة الرمز فقط)، `rate_limits` (بصمة IP فقط).

## تدفق الطلب

1. السلة تُحفظ في `localStorage` (مع بديل في الذاكرة) وتتزامن بين التبويبات.
2. الأسعار الحية تُجلب من `/api/catalog` وتُدمج في البطاقات والسلة والتصفية.
3. النموذج يتحقق من المدخلات في المتصفح، ثم يعيد الخادم التحقق بنفس المخطط (`src/lib/order/validation.ts`).
4. «تأكيد الطلب» ← `POST /api/orders` ← رقم طلب حقيقي وإيصال، وتُفرغ السلة.
5. إذا تعذر الحفظ (الخادم أو قاعدة البيانات غير متاحين) يعرض الموقع ذلك ويقترح واتساب، ولا يعرض رقم طلب.
6. لوحة التحكم تتابع الطلبات كل 20 ثانية أثناء فتحها، مع تنبيه مرئي وصوتي اختياري.

## ما هو غير موجود (عمدًا)

- لا دفع إلكتروني، ولا حسابات عملاء.
- التتبع الوحيد: بكسل TikTok (`src/lib/tiktok-pixel.ts`) ويعمل فقط على etaadq8.com: مشاهدة الصفحات، ViewContent، AddToCart، InitiateCheckout، PlaceAnOrder (برقم الطلب المحفوظ كـ event_id)، و Contact عند فتح واتساب. بيانات منتجات عامة فقط، بلا بيانات عميل.
- لا إشعارات بريد أو Push خارج لوحة التحكم. التنبيه يعمل واللوحة مفتوحة.
- إضافة منتج جديد (اسم، صور، وصف) تتم في الكود حاليًا. الأسعار والتوفر من اللوحة.

## التوسع المستقبلي

البنية مهيأة لذلك دون إعادة كتابة الواجهة:

1. **مصدر البيانات**: استبدال محتوى `src/lib/catalog.ts` بقراءة من قاعدة بيانات (مثل Cloudflare D1 أو Postgres). الواجهات تستخدم `getAllProducts / getProduct / getActiveCategories` فقط. المخطط في `src/lib/schema.ts` يصلح أساسًا لجداول `products`, `categories`, `product_images`.
2. **التحديث**: إما إعادة بناء الموقع الثابت عند كل تعديل (Deploy Hook)، أو الانتقال إلى وضع الخادم في Next.js (إزالة `output: 'export'`).
3. **الطلبات**: إضافة نقطة API تستقبل نفس كائن `CheckoutData` + `OrderLine[]` (المعرّفين في `src/lib/order/`) وتحفظ الطلب قبل فتح واتساب — عندها فقط يمكن إصدار رقم طلب حقيقي.
4. **الحماية**: لوحة التحكم تحتاج مصادقة حقيقية (مثل Cloudflare Access أو مزود هوية)، وتحقق من الصلاحيات على الخادم، وسجل تدقيق، وحماية CSRF. لا تبنِ لوحة بكلمة مرور في الواجهة الأمامية.
5. **المخزون**: الحقل `availability` موجود؛ يمكن إضافة `stockQuantity` لاحقًا مع إبقاء `unconfirmed` كحالة افتراضية.
